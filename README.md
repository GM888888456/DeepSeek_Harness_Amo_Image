# 我想永远陪着你 · 相片（Astrbot_Amo_Image）

## 2.6.7

**审核预检：`config_guard` 收紧，不再读别的插件的配置。**

- 旧配置只从本插件自己的文件回填：同名文件（含它自己的 .bak 备份）、显式登记的旧目录名
  （`legacy_names`）、本插件名 + 下划线开头的改名前缀。
- `api_key`、token、密码、接口地址这类敏感键连改名前缀的旧文件也不认，只认同名文件和快照。
- 日志本来就只有 `astrbot.api` 一个来源，网络请求也都已在线程里跑，这次没动。

## 2.6.6

**同一套衣服一天一个朝代：形制从来没写进提示词。**

`pattern_clause()` 只按套名固定了【布料纹样】（料子、绣花、暗纹、格纹），
形制（宋制/明制/唐制）一个字都没写。模型看到「褙子」就自己发挥：今天是宋制
直领对襟，明天成明制立领，后天干脆画成和服。

- 新增 `SET_FORM`（套名 → 朝代形制句）+ `form_clause()`：长安月=唐制齐胸襦裙、
  棠梨煎雪=明制立领袄+马面裙、听雨/雪霁=宋制对襟褙子、竹林雪=宋制交领襦裙、
  未央=汉制曲裾、青鸾=明制圆领袍、琉璃=唐制坦领半臂；表里没有的汉服走兜底句
  「按同一朝代形制画，不许混搭、不许画成和服/韩服/影楼装」。
- `build_prompt()` 在纹样句后追加形制句；正文已经写了形制词（宋制/立领/马面裙…）
  就不再追加，避免一句提示词两套形制打架。

**同时修的三个线上问题：**

- **200 + 0 字节空包自动重试**：站点偶发返回空响应体，旧代码 `json.loads("")`
  抛 `Expecting value: line 1 column 1 (char 0)`，一次失败整轮出图就没了。
  现在重试 3 次（1.5s / 3s 退避），错误里带上 `server`/`cf-ray`/`content-length`，
  能看出是哪一层吐的空包。
- **拉模型列表统一补 `/v1`**：`api_base` 填 `https://api.syuan.org`（不带 /v1）时，
  出图那条路会自动补（`_endpoint()`），但拉列表直接拼 `base + "/models"` 打不通，
  于是原生设置页的下拉里一直留着上一站的旧模型名，看起来像「模型被固定死了」。
  现在抽 `_api_root()`，出图 / 拉列表 / 面板拉取共用。
- **配置热同步**：`_cfg()` 里做 1 秒节流的 `reload_if_changed()`。原来只有面板接口
  才会读配置文件，用户在设置页把 `api_base` 换成新站，出图却一直连旧站
  （`Cannot connect to host api.syuan.org`）。
- **原生设置页的「生图模型」变成下拉**：启动时拉一次 `/models`，把图片模型写进
  `_conf_schema.json` 的 `model.options`（重载后生效，换站重载即刷新）。

## 2.6.5

**接口地址少了 `/v1`，生图会「假故障」。**

- 现象：配置里只填站点根地址时，`/images/generations` 会命中网站首页、返回 HTML，
  解析 JSON 直接抛 `Expecting value: line 1 column 1 (char 0)`，看起来像接口坏了。
- 修法：`_endpoint()` 自动补 `/v1`（已经带 `/v1` 的不动）。
- 另外：`core_appearance` 默认值改为留空，兜底长相换成通用默认——
  仓库里不该带某个具体角色的长相。装好之后请自己填角色的长相。

## 2.6.4

**市场上的新衣服也有固定花纹了（按「款式 + 颜色」自动生成）。**

- 新增 `consistency.market_pattern()`：市场衣服名字形如「汉服·唐制黑齐胸襦裙」
  「JK·粉格裙」「黑风衣」，没有套名可查表，于是按「款型 + 颜色」推一条**确定**的花纹。
  同一个名字永远同一句。26 种款型（齐胸襦裙/百迭裙/马面裙/圆领袍/深衣/褙子/水手服/
  衬衫/格裙/风衣/卫衣/牛仔/连衣裙/裤装/鞋袜/发饰/领饰/挎包…），双色（黑白）会保留。
- `set_pattern()` 现在两条路：内置 20 套查 `SET_PATTERN` 表；查不到就当市场衣服走
  `market_pattern()`；款式也认不出才退回纯色。**以后市场新上架的款式自动有花纹，
  不需要人工维护表**。
- 全量 **195 绿**（新增 6 条市场衣服测试）。

## 2.6.3

**锁骨那颗痣去掉；同一套衣服的花纹不再每张都不一样。**

- 长相表 `core_appearance`（以及 `self_face.DEFAULT_APPEARANCE`、schema 默认值）里
  「左锁骨有一颗很小的痣」改成「皮肤干净、没有任何痣和胎记」，三处必须同源：
  配置自愈会拿 schema 默认值和快照把它们互相写回，改一处等于没改。
  终端那条 `【我自己的样子】` 永久记忆是照这段生成的，也一并改了。
- 新增 `consistency.SET_PATTERN` / `set_pattern()` / `pattern_clause()`：衣柜里 20 套
  衣服各钉一条固定纹样（格裙的格子怎么排、汉服的绣花暗纹什么样）。衣柜本来只写
  「樱粉格裙」「织金马面裙」，布料全靠模型当场发挥，同一天同一套的几张照片看起来
  像三件不同的衣服。认不出的套名一律退回纯色，不让它自己编花纹。
- `build_prompt` 给有穿搭的提示词补一条「布料纹样（必须一致）…」；正文已经交代过
  布料（命中两个以上纹样特征）就不再追加，避免同一张图两套花纹描述打架。
- 负向词补 `mole / beauty mark / birthmark / freckles / 痣 / 胎记` 与
  `different fabric pattern / changed plaid pattern / different embroidery / 花纹不一致`。
- 新增 `tests/test_pattern_and_mole.py`（10 条）。全量 **189 绿**。

## 2.6.2

**照片里衣服前后不一（前一张交领、后一张抹胸）：穿搭只留一处真相。**

- `build_prompt` 原来只比「整串穿搭是否原样出现在正文里」——正文只写了一件
  （「穿着汉服·雪霁｜对襟褙子」，裙袜鞋都没写）就判成「没写」，于是又追加一条完整四件套，
  同一张图里两句衣服描述互相打架，出图看哪句都说得通。现在只要正文出现这套的任一件，
  就以正文为准，不再追加。
- `_scheduled_outfit` 遇到「只剩一件」的半套时，按套名 `compose_set` 补回整套；
  补不上就原样返回——宁可只有一件，也不能编不存在的衣服。
- 把只存在于机器上的 `self_face.py`（自我形象档案/认人）和 `core_appearance`
  等配置键收进仓库：2.6.1 那次升级把它们覆盖掉了，认人和档案一度全哑。

## 1.7.3（面板读不到数据的真正原因）

- 根因：AstrBot 把 `bridge-sdk.js` 注入在 `app.js` **之后**（实测页面里 56 行是 app.js、
  57 行才是 SDK）。这三个面板在脚本开头就 `const bridge = window.AstrBotPluginView`，
  那一刻全局还不存在，于是 `bridge` 永远是 `null`——所有 `get()` 都返回空，
  面板自然「读取不到」，而语音面板是每次调用重新找桥接，所以它一直正常；
- 改成：每次请求都 `resolveBridge()` 重新解析；启动时 `waitForBridge()` 最多等 6 秒再加载；
- 用 Node 模拟「先执行脚本、后注入 SDK」验证：注入前返回 null 不抛错，注入后正常拿到数据。

## 它和另外两个插件怎么联动

| 联动点 | 来源 | 行为 |
|---|---|---|
| 人物外观 | 本插件 `character_appearance` | 拼在提示词最前面，保证每次是同一个人 |
| 剧情上下文 | 数据插件（`Astr_Amo_data`） | 读最近几句对话补进提示词，让画面接得上剧情 |
| 人设化失败话术 | 本插件 `error_reply` | 后端挂了也只回一句人设话，不抛异常 |

## 安装

1. 把 `Astrbot_Amo_Image` 目录放进 AstrBot 的 `data/plugins/`；
2. 重启 AstrBot，在 WebUI 的插件页启用；
3. 在插件配置里填 `api_base` / `api_key` / `model`，至少这三项。

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `api_base` | `https://api.openai.com/v1` | OpenAI 兼容根地址，请求 `{api_base}/images/generations` |
| `api_key` | 空 | 只存本机配置，不会写进日志 |
| `model` | 空 | 后端支持的模型名；留空用后端默认 |
| `size` | `1024x1024` | 尺寸 |
| `n` | `1` | 每次张数 |
| `quality` / `style` | 空 | 留空就不发这个字段，兼容不支持的旧后端 |
| `timeout` | `90` | 生图超时（秒） |
| `character_appearance` | 空 | 人物外观描述 |
| `use_memory_context` | `true` | 是否用数据插件补上下文 |
| `memory_context_limit` | `6` | 取几条对话 |
| `allow_private` / `allow_group` | `true` | 私聊 / 群聊是否可用 |
| `require_at_in_group` | `true` | 群里必须真 @ 机器人才画（唤醒词不算） |
| `quote_in_group` | `true` | 群里发图时引用原消息；私聊永远不引用 |
| `keywords` | 画一张 / 画个 / 帮我画 / 生成图片 / 来张图 / 画张 | 触发词 |
| `cooldown_seconds` | `30` | 同一人冷却 |
| `private_daily_limit` | `0` | 私聊每人每天次数，`0` 不限 |
| `group_daily_limit` | `20` | 每个群每天次数，`0` 不限 |
| `safe_mode` | `true` | 内容边界：私聊拦露骨裸体/性器官/性行为/未成年相关，群聊额外拦只穿内衣/比基尼 |
| `blocked_reply` | 这个画不了，换个描述吧 | 命中内容边界时的回复 |
| `reply_prefix` | 空 | 发图前带一句话 |
| `error_reply` | 画不出来，等会儿再试试 | 失败话术 |

## 内容边界

`safe_mode` 打开时：

- 私聊：只拦露骨裸体、性器官、性行为、未成年相关；比基尼、内衣这类日常向描述放行；
- 群聊：额外拦「只穿内衣 / 内衣照 / 比基尼 / 情趣内衣」；
- 记忆上下文、`draw_for` 分享入口走同一套判定，群友往聊天里塞「画裸体」不会顺着拼进提示词；
- 提示词注入词（「忽略之前」「system prompt」「越狱」）一律拦。

这是一层关键词 + 正则防线，挡不住谐音、外语、拆字和极端变体；要更稳需要图片返回后加 NSFW 输出检查，
插件不内置这类模型，避免偷跑第三方服务。

「必须真 @」依赖消息里的 `At` 组件。QQ 没问题；Lark / Telegram 这类平台如果 mention 不走 `At`，
可能出现「@ 了也不触发」，到时候要按平台补一个判定分支。

## 用法

- 私聊：`画一张 下雨天的便利店门口`
- 群聊：`@机器人 画一张 她在天台看晚霞`（必须真 @，唤醒词不算）
- 命令：`/amoimage status` 看后端与今日额度；`/amoimage draw <提示词>` 手动出图

## 后端兼容

- `provider=openai`：`/images/generations`，认 `data[].url`、`data[].b64_json`、`images[].url`；
- `provider=openai_chat`：`/chat/completions`，认 markdown 图片链接和 `message.images`；
- `provider=gemini`：原生 `generateContent`，认 `candidates[].content.parts[].inlineData`；
- `provider=custom`：完整 URL + 请求体模板 + 响应路径，接非标准端点；
- `url` 模式会先把图片下载成字节再发，避免平台裂图；
- `url` 模式若下载失败、`b64` 解析失败、接口 4xx/5xx、超时，统一降到 `error_reply`；
- one-api / new-api / 自建 SD 兼容层只要实现了 `/images/generations` 就能用。

## 版本号规则

- 三段：`x.y.z`，**第二位和第三位只能是 0-9，逢十进一**：3.8.9 → 3.9.0，3.9.9 → 4.0.0；
- **首位不做限制**，可以是多位数：9.9.9 再进一位是 10.0.0（不是 1.0.0.0）；
- **测试版**：动第三位（7.4.0 → 7.4.1）；
- **发布版**：动第二位、第三位归零（7.4.1 → 7.5.0）；
- **大版本**：首位 +1（7.5.0 → 8.0.0）；
- `python3 tools/check_version.py` 校验四处一致与规则，
  `python3 tools/check_version.py --next test|release|major` 直接算下一个号。
